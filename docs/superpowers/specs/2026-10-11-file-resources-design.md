# Named text file resources

The continuing user goal authorizes implementation toward agent-usable general programming. This slice adds actual text file reads/writes through Specs -> checked Core -> STE -> bytecode -> VM/native ELF. It does not claim Python replacement completion or full ASD-STE100 conformity.

## Contract

- Source: `the system reads text from file resource input into data.text`; `the system writes text data.text to file resource output`.
- Resource names are static ASCII identifiers, optionally dot-separated (each segment starts with a letter/underscore, then letters/digits/underscores), at most 256 bytes. Imported resource names receive the import alias prefix.
- Read/write fields must be global `Text`. Application and C interop profiles support these operations; compiler pass bodies and integer functions do not. Derived semantic field reads/writes participate in secret checks.
- Core: `FileOperation` with exactly `file_kind=read|write` and `resource=<name>` attributes; exactly one `file_step` Action owner with valid ordering metadata; exactly one `file_destination` (read) or `file_source` (write) typed global field, no extra semantic edges or attributes.
- Bytecode: `FILE_READ_TEXT` with exactly `resource,key`; `FILE_WRITE_TEXT` with exactly `resource,source`. STE templates: `Read text from file resource {resource} into field {key}.` and `Write text from field {source} to file resource {resource}.` Operands use the existing STE data declarations.
- Caller authority is separate from package capability metadata and runtime state. VM API `AilFileResources { reads: BTreeMap<String, PathBuf>, writes: BTreeMap<String, PathBuf> }` and `run_ail_bytecode_action_with_files(program, action, state, &resources)`; existing APIs default to no grants. CLI/native flags are single arguments `--read-file=<resource>=<path>` and `--write-file=<resource>=<path>`. Duplicate bindings use the last one. Names/paths must be nonempty and paths cannot contain NUL. An ordinary field assignment cannot grant permission. Validate all supplied bindings (including unused maps in the public API) before execution. Direct bytecode and STE enforce the same supported profiles as Core.
- Bindings grant access to that exact caller-selected path as resolved by the host at operation time; symlinks follow normal host semantics. These bindings are not directory confinement or a sandbox for arbitrary binaries. Programs cannot select or construct filesystem paths. A resource can have separate read/write bindings. Grants are shared through action calls.
- Read opens the file each time and reads from its start through EOF. Write opens/creates (mode 0666 subject to umask), verifies a regular file, truncates, and writes exact UTF-8 bytes (no added newline). Parents are not created. On Linux open uses O_NONBLOCK to avoid blocking on a FIFO before type checks. Directories/devices/FIFOs/sockets are rejected. No durability guarantee; close errors ignored. Read and write syscalls retry EINTR; writes handle short progress.
- Read validates a maximum of 1,048,576 bytes and strict UTF-8, then charges the existing shared 64 MiB text allocation budget by max(length,1), then atomically updates the destination. Read scratch is bounded and reclaimed. Writes validate a present, bounded Text source before opening/truncating the target. NUL bytes inside text are valid.
- Errors: absent resource grant `AIL-RUNTIME-CAPABILITY`; host/type/open/read/write failure `AIL-RUNTIME-IO`; missing/invalid UTF-8 Text `AIL-RUNTIME-TEXT`; oversize/budget `AIL-RUNTIME-TEXT-LIMIT`. Check grant before field value/file access; read size before UTF-8, then allocation budget. No paths/content in traces; success trace identifies operation and resource only.
- File effects occur in source execution order, including branches/loops/calls. A later error does not roll back completed writes; write errors can leave a partial or truncated file. Output field selection remains the existing final output behavior.

## Validation

Contract tests must cover source, saved Core, rendered source, imports, STE, bytecode, VM and direct ELF; denied/reversed grants, runtime-state spoof attempts, UTF-8/NUL/empty/exact/over limit, truncation, directories/FIFOs, missing paths, loops/calls/order, immutable aliases, malformed Core/protocol, and secret checks. An independent Python oracle compares read/transform/write files across VM/native. Preserve the frozen capability ladder and existing corpus.

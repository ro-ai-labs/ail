# Reusable LRU Cache Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a pure persistent-state LRU API, independently measured R024,
and bounded stdin request tool through every public VM/native execution route.

**Architecture:** A Json state holds capacity and unique ordered entries from
LRU to MRU. Existing pure Json operations implement lookup/promotion/eviction;
batch and request adapters reuse those transitions. The oracle uses OrderedDict
and a separate list model, with lossless ordered-pair/number-token payloads.

**Tech Stack:** Existing AIL source, checked Core, STE, VM/native compiler;
Python standard-library oracle/harness; unchanged bounded process runner.

**Spec:** [LRU cache design](../specs/2026-10-12-lru-cache-design.md).

## Global Constraints

- Package `ail.std.lru` 0.1.0, Application profile, imported as `LRU` from
  `examples/ail_std_lru.ail`; standalone app `examples/lru-cache`.
- Exact signatures: `create(capacity:Int)->Json`, `get(state:Json,key:Text)->Json`,
  `put(state:Json,key:Text,value:Json)->Json`,
  `run(capacity:Int,operations:Json)->Json`, `runRequest(text:Text)->Json`.
- State is exactly capacity then entries, LRU→MRU; normalize capacity -0 to 0.
  Entry names are unique exact Unicode; payloads retain ordered duplicates,
  number lexemes and decoded strings. Get hit promotes, miss preserves recency;
  replacement promotes without unrelated eviction; zero capacity stores nothing.
- Exact result/event/error shapes and priority are binding in the spec.
  Direct domain errors use existing VALUE. Request response strings are
  REQUEST, CAPACITY and OPERATIONS, with explicit scoped validation.
  Malformed direct typed transports and existing fatal bounds are not remapped.
- All cache code is pure ordinary AIL. No compiler/runtime/old script/test/rung
  edits, dependency, host cache, arbitrary small cap, budget change or padding.
- Analyze consumes data.request:Text and selects only out.result:Bytes with
  trace Simulated, encoding the exact result Json as UTF-8. App/bench body matches.
- Run reads one raw request through EOF and emits compact result plus one LF.
  Structured domain errors exit zero; grant/UTF-8/fatal errors are nonzero with
  no result stdout/leak. Every fallible input/result step precedes the only write.
- No git mutation, commit, cleanup, installation, network or publication.
  Preserve existing work; root owns metadata, score and whole-milestone review.
- Freeze an independently reviewed oracle and demonstrate real missing-program
  RED before AIL implementation. Never derive expected cache behavior from AIL.
- Finite subprocess deadlines, process cleanup, full output bytes and exact input/
  dependency/artifact hashes. Preserve failed/interrupted attempts honestly.

## Review Focus

1. Cached null versus miss; lookup promotion versus FIFO; replacement in a full
   cache must not evict an unrelated key. Distinguishing traces pin each transition.
2. Empty/NUL/slash/tilde/numeric/Unicode keys and normalization variants;
   escaped-equivalent duplicate entry/selected keys reject, payload duplicates survive.
3. Caller-supplied state with reordered fields, -0, overfull entries, duplicate or
   extra state fields; normalize valid states and reject bad shapes without mutation.
4. Full request/operation validation, ignored fields and duplicate names; malformed
   late operations produce no partial success and error priority stays deterministic.
5. Full Unicode report transport and immutable copying at useful sizes; long keys,
   large number tokens, nested payloads and cumulative limits must not truncate or leak.
